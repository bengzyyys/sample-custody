# 本地样品流转与保管链

这是一个在本机运行的本地样品流转与保管链。数据保存在本地单个 JSON 文件中，
不依赖任何外部服务。

## 使用

```bash
go test ./...
```

测试通过表示包可以加载且登记、分装、交接、持久化行为符合规则。

## 公开入口（package custody）

通过文件路径创建或重新打开一份本地样品数据（不存在则新建，已存在则恢复）：

```go
s, err := custody.Open("sample-data.json")
```

所有数量以毫升为单位，只接受大于零、最多三位小数的十进制字符串，查询时
统一显示三位小数；内部以千分之一毫升整数精确计算，分装扣减不会因舍入
多出或丢失样品。所有被拒绝的操作都不会改变数量、当前位置、历史或待确认
记录。

### 登记原样

```go
s.Register(custody.RegisterInput{
    ID:       "S-001",
    Qty:      "10.000",   // > 0、最多三位小数
    Holder:   "张三",
    Location: "实验室A",
})
```

编号在这份数据内唯一；编号、持有人、地点去掉首尾空白后不能为空。

### 分装

一次分装可以创建多个子样，各子样有独立编号；子样总量不得超过来源样品的
剩余量。任一编号重复或数量不合法，整次分装都不生效。成功后精确扣减来源
样品剩余量，子样继承当时的持有人和地点，并能继续分装。父样与子样此后的
交接互不带动。

```go
s.Split(custody.SplitInput{
    ParentID: "S-001",
    Parts: []custody.SplitPart{
        {ID: "S-001-A", Qty: "4.000"},
        {ID: "S-001-B", Qty: "6.000"},
    },
})
```

### 交接

发起交接需提供本次交接编号、交出人、交出地点、指定接收人、目的地点和
交出时间。交出人和交出地点必须与样品当前记录一致，接收人不能与交出人
相同。交接转移该样品全部剩余量，发起后处于待确认，原持有人和地点保持
不变；同一样品已有待确认交接时，不能再次发起交接或分装。

```go
s.Handover(custody.HandoverInput{
    TransferID:   "TR-001",
    SampleID:     "S-001-A",
    FromHolder:   "张三",
    FromLocation: "实验室A",
    ToHolder:     "李四",
    ToLocation:   "实验室B",
    HandedOverAt: handedAt,
})
```

只有指定接收人能在目的地点确认接收，接收时间不能早于交出时间。确认后
才改变持有人和地点，并结束待确认状态。

```go
s.Confirm(custody.ConfirmInput{
    TransferID: "TR-001",
    Receiver:   "李四",
    AtLocation: "实验室B",
    ReceivedAt: receivedAt,
})
```

### 销毁

销毁处理该编号样品**当时的全部剩余量**，不接受部分销毁。操作人和所在
地点去掉首尾空白后必须与样品当前持有人、地点一致；样品必须还有剩余量，
且没有待确认交接。成功后剩余量变为 0.000，初始量、来源关系、子样列表
和原有保管历史保留，持有人和地点保留为销毁前的最后记录，保管历史末尾
追加一次销毁事件，并返回该样品的最新查询结果。

```go
view, err := s.Destroy(custody.DestroyInput{
    SampleID: "S-001-A",
    Operator: "李四",
    Location: "实验室B",
    At:       destroyedAt,
    Reason:   "实验结束按规程销毁",
})
```

销毁时间不能为零，也不能早于该样品任何已有保管历史的时间（相同时间
可以接受）。父样与子样各自独立：销毁父样不改变已经分出的子样，销毁
子样也不再扣减父样。

已销毁样品重复提交与首次完全相同的操作人、地点、时间和原因时，返回原
销毁结果且不再追加历史（文本按去空白后比较，时间按实际时刻比较）；
改变任一项则返回 `ErrConflict`，不覆盖原记录。已销毁样品不得再分装或
发起新的交接；其既有已确认交接的相同交出、接收请求仍按原规则返回原
记录，不改变销毁状态。

### 幂等重复提交

交接编号在本地数据中唯一。重复提交同一编号且内容（样品、人员、地点、
时间）完全相同的交出请求，返回原交接，无论它是否已确认；沿用编号但改变
任一项则拒绝。已确认交接重复提交相同接收信息仍返回原结果，不增加转手
记录；接收信息不同则拒绝。

### 查询

按样品编号查询能看到来源样品、初始量和剩余量、当前持有人和地点、分装
产生的子样，以及按发生顺序排列的保管历史和待确认交接详情。剩余量为
0.000 时，凭销毁信息区分“分装用尽”（无销毁记录）和“已销毁”（带操作人、
地点、时间、原因和实际销毁量）；未销毁样品没有销毁记录：

```go
view, err := s.GetSample("S-001")
transfer, err := s.GetTransfer("TR-001")
```

不存在的样品或交接返回包装了 `custody.ErrNotFound` 的明确错误，不会顺带
创建记录。错误类型可用 `errors.Is` 区分：`ErrInvalid`（入参非法）、
`ErrConflict`（状态冲突）、`ErrNotFound`（记录不存在）。

### 重新打开

关闭后重新 [Open] 同一文件，样品记录、父子关系、保管历史、待确认状态、
销毁信息与后续操作限制、交接编号及销毁请求的重复提交判断全部仍然有效。
旧数据中没有销毁信息的样品一律视为未销毁，即使剩余量为零也不会推断为
销毁。每份未销毁样品恢复时还要核对自身数量：自身初始量必须大于零，剩余
量可以为零（旧的分装用尽约定不变），但不能为负、也不能超过自身初始量；
这一规则对登记的原样和分装产生的子样同样适用，子样的上限是它自己创建时
取得的初始量，不能借用父样或其他样品的量。样品是否挂有待确认交接不影响
这项检查：即使交接量恰好与错误的剩余量一致，数量越界的样品也会被拒绝。
任一记录不符，整份文件打开失败，返回包装了 `ErrInvalid` 的错误（不返回
Store、不改写原文件、不自动把剩余量改成零或初始量、也不跳过错误记录只
加载其他样品），错误信息写明样品编号、违反的数量规则，并以三位小数毫升
展示初始量与剩余量；现有数据格式可表示的极端负数量同样正常返回错误。
对带有销毁信息的样品，恢复时还要核对销毁数量是否守恒：当前剩余量
必须为 0.000，参与核对的自身初始量与实际销毁量都大于零，且实际销毁量
加上它直接分出的各子样创建时取得的初始量之和，恰好等于该样品自身的
初始量（没有分出子样时实际销毁量就应等于初始量）。参与核对的子样关系
必须一致：子样列表中的每个编号都对应现存样品、其来源编号指向本样品且
每个编号只出现一次；反过来，来源编号指向本样品的子样也必须全部列在
列表中。同一子样重复列入、把来源不符的样品（另一份原样的子样或没有
来源的原样）列进来、或漏列真正的直接子样，都会使来源关系自相矛盾，
即使数量合计碰巧等于初始量也按无效数据拒绝；不能通过删除重复项、忽略
漏列项或改写子样来源来接受文件。这一关系核对同样适用于已销毁的分装
子样：它的分出量只来自自己直接创建的子样。这里统计的是各直接子样创建
时取得的量：子样后来继续分装、转交或销毁都不改变原样当时已经分出的量，
不会改用子样当前剩余量，孙样也不重复计入；同一份数据里的其他原样不
参与这次核对。数量仍按 0.001 毫升精度核对，支持上限附近的合法数量
准确恢复，合计超出支持范围时按无效数据处理。任一销毁数量记录不符合
上述关系，整份文件打开失败，返回包装了 `ErrInvalid` 的错误（不返回
Store、不改写原文件、不只加载其他正常样品），错误信息写明有问题的已
销毁样品编号、涉及的子样编号，以及重复列入、来源不符、漏列或数量
不符的具体原因；数量不符时以三位小数展示初始量、销毁量与直接子样
总量。待确认交接代表样品当前全部剩余量尚待指定人员接收，恢复时其
交出人、交出地点、交接量必须分别与样品当前持有人、当前地点、当前
剩余量一致，且样品未销毁、剩余量大于零；任一不符整份文件打开失败，
返回包装了 `ErrInvalid` 的错误（不返回 Store、不改写原文件），错误
信息会写明样品编号、交接编号与冲突项。已确认交接保存的是当时发生的
转手，其人员、地点与样品现状不同不受此限制，但每条已确认交接恢复时
还必须通过自身核对：它必须关联到一份实际存在的样品记录（含被 null
占用的损坏条目），且交接量大于零、不超过该样品自身的初始量。这一
上限对原样和分装子样相同：原样取登记量，子样取它创建时分得的量，
不能借用父样、兄弟子样或其他原样的量（子样自身初始 3.250 毫升却
留着 4.000 毫升的已确认交接，即使父样初始量为 10.000 毫升也必须
拒绝）；交接量恰好等于样品自身初始量属于合法边界。上限是样品自身
初始量而非当前剩余量，也不能把同一样品多次转手的交接量相加后比较：
原样曾以 10.000 毫升完成交接，之后分出 3.250 毫升、再以剩余的
6.750 毫升转交时，两条旧交接都按当时数量原样保留；样品后来换了
持有人、地点或被销毁，只要原有数据符合规则仍能正常恢复并查询。任一
已确认交接关联的样品不存在，或交接量为零、为负、超过样品自身初始量，
整份文件打开失败，返回包装了 `ErrInvalid` 的错误（不返回 Store、
不改写原文件、不删除问题交接、不替它补登记样品或调整数量，也不只
加载其他正常样品和交接），错误信息写明交接编号、关联样品编号与
具体原因；数量不符时同时以三位小数毫升展示交接量与样品自身初始量。
落盘采用临时文件加原子替换。
